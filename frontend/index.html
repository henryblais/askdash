How it works

The problem. Executives want to ask questions of a dashboard, not learn its filters. Every "can you add a view that…" became a ticket.

The approach. The dashboard state (each panel's title, SQL and chart spec) is sent to an LLM along with a curated schema and your request. The model returns one JSON action: add, replace, remove or answer — with the SQL and a chart spec.

Safety. Model output is never trusted. SQL passes a static check (single SELECT, deny-listed keywords), then a SQLite authorizer that refuses anything but reads of allow-listed tables, on a read-only connection with a 5s timeout and a 500-row cap. Rate limits and a daily budget protect the API bill.

Reliability trick. The schema the model sees is a single flattened sales view with revenue, cost and margin precomputed. Fewer joins means far fewer wrong answers.

Stack. Python (FastAPI or stdlib server), SQLite, Claude via the Anthropic API, and a dependency-free SVG chart renderer in the browser. Click SQL on any panel to see exactly what ran.

No API key? The server falls back to a rule-based planner so the demo still works end to end (that's what mock in the header means).
